# DdakKok — Contribution Case Study

**Project:** 딱콕 · 2026 SSAFY × Kakao Tech AI Hackathon  
**My role:** Product/AI architecture and system integration contributor; frontend lead  
[Public frontend](https://github.com/peanut-works/ddakkok-web) · [English setup and demo guide](ddakkok-frontend-guide.md)

## Problem

Caregivers need help checking product ingredients against a child's allergy and health information. The project presents child-specific alerts and explanations to make that review easier.

## My contribution

- Contributed to the overall product/AI architecture and system integration.
- Led frontend development.
- Designed a workflow connecting ingredient information, child profiles, and conservative alerts with explanations.
- Supported user-needs validation through teacher interviews.

## Deliverables and recognition

- A team prototype of the ingredient-review workflow.
- A public React and TypeScript presentation frontend.
- Korea Chamber of Commerce and Industry Chairperson's Award, 2026 SSAFY × Kakao Tech AI Hackathon.

The award belongs to the team. No adoption, accuracy, revenue, or time-saving metric is claimed.

## Technical evidence

The public web repository uses React 18, TypeScript, Vite, React Router, and an API client that connects to the separate FastAPI backend. It includes local mock-data fallback and browser-only child-profile edits for presentation purposes.

Read the [English guide](ddakkok-frontend-guide.md) for routes, setup commands, source-file links, and known limitations.

## Verification boundaries

The repository sources and existing README were inspected for this case study. No new build or automated test pass was executed or claimed during documentation preparation.

The frontend's mock results are presentation data, not live AI inference. Its seeded waitlist count is not a measured user-acquisition result. This demo is not evidence of clinical validation or production readiness.
